# V132: specific teaching and worked references

This release merges the concurrent `feature/v131-unified-tutor` snapshot 37758ca8dfdc5dbc2de322be81d790c5ca90379a, including its curiosity features, direct checked-tutor entry and mobile table/dialog fixes. V130's retained working notes, step synchronization, audio support and local dictation safeguards stay in place. Earlier generated HTML editions remain available.

The main addition from this pass is authored teaching content. Eight lessons now have **51 individually written prompts, hints and explanations of sticking points**, aligned to their actual worked steps. They cover two-hand piano coordination, rests and subdivisions, Spanish noun groups and café repair, chess exchanges and castling, the product rule, and sled energy. Asking for help on the width strip, for example, explains the 4 m/s rate acting along the 3 m length. It no longer returns the same subject-wide nudge used for every calculus step.

Three further checked coaching scenarios cover a silent piano beat and half-beat timing, recovering a café question and confirming an order, and the two-piece movement and attack restrictions of castling. They add nine decisions and eighteen specific help branches to the earlier fifteen decisions. All eight checked coaches have a directly visible **Work this out with feedback** entry beside the first worked problem. Optional comparison of a learner's own reasoning remains available separately.

The three new scenarios show their worked references before an answer is required. Piano uses a beat/time/action table. Spanish keeps the complete exchange and translation beside each question, with Spanish language markup. Chess shows the before/after castling positions and the forbidden crossing-square example, with text descriptions. These diagrams are references; the original playable lesson boards and piano/audio demonstrations remain.

Spanish checks accept several natural repeat requests, takeout replies and confirmation forms. Unrecognized wording receives a comparison, not a claim that it is invalid Spanish. The checks distinguish the two-option question from confirmation and point out the accent in sí. New square checks distinguish the king's destination from the rook's and the crossing square. Numeric timing checks match the actual existing note schedules. Arbitrary working notes and musical performance are not graded.

The concurrent curiosity feature is retained as optional practice. Course maps can offer a real authored question near the current reading place, with its explanation available immediately. A project/workshop bookmark opens the full course pool. Misconception comparisons remain folded after the teaching, with a **Read the worked correction** route that requires no choice. Eight new concise comparison pairs avoid putting a complete long repair paragraph against a short wrong answer in the selected lessons. These activities do not write assessed success, progress or mastery.

The content files are additive: `specific-teaching-v132.json` supplies aligned prompt/hint/help records and comparison pairs; `step-coach-v132.json` supplies the three new scenarios. The five V128 scenario records, all V130 display revisions, demonstration models, 87 base course records, projects, workshops and 208 unrelated archived assets remain unchanged. The existing reading, audio, recovery and backup paths stay intact.

Verification checks alignment against the actual displayed V126/V127 revisions, independent note times and castling legality, all 24 checked decisions and accepted language variants, the 51 rendered teaching turns, direct coach access, optional correction access, reference tables and SVG descriptions, keyboard behavior, unchanged saved values, and phone layouts in both themes. Speech checks use controlled API mocks; a real microphone, subject expert review and learner comprehension have not been verified. Current release checkpoints record local test and GitHub delivery status separately from hosted CI or Vercel deployment.

Vercel serves the committed `public/` artifact directly. Lesson generation requires Python/chess tools already installed for development and CI, so it is kept out of the static deployment path. CI now verifies that the committed HTML matches source before tests instead of silently rebuilding stale output. Hosted deployment status still requires separate verification.
